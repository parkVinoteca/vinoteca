# v1.3 — 평가 입력 정비

상태: 구현·로컬 검증 완료. 사용자 승인으로 운영 DB 변경 적용 및 타입/제약/RLS 확인 완료(2026-09-19). 앱 병합·배포 상태는 GitHub PR #8 참조.

## 동작

- 두 모드 모두 개인 평점 1.0–5.0, 0.1 단위. 미평가는 NULL. `stars`를 새 평점의 단일 저장 필드로 사용한다.
- 과거 기록은 변경하지 않는다. 기존 stars가 유효하면 우선 사용하고, stars가 없으면 score/2를 표시한다. 과거 1/10은 0.5/5로 그대로 환산 표시된다. 셀러 상세에서 과거 점수임을 안내한다.
- 홈 평균·셀러 정렬·상세·취향 분석은 같은 변환 함수를 사용한다. 점수를 매긴 모든 기록의 상대적 높고 낮음을 활용한다. 구조나 평점 차이의 근거가 부족하면 매칭을 계산하지 않는다.
- 3.5 보통으로 즐길 만함, 4.0 취향에 맞음 등의 안내는 Vinoteca 개인 기록용 기준이다. 업계 공통 규칙이나 Vivino 공식 등급으로 주장하지 않는다. 전문가 100점 평가와 환산하지 않는다.
- WS(Wine Spectator), WA(Wine Advocate), JS(James Suckling) 수동 입력 제거. 기존 수동 점수 데이터는 삭제하지 않지만 출처 확인된 점수처럼 표시하지 않는다.
- 전문가 점수 자동 검색은 실측 후 사용자 선택으로 껐다. 품종이 없을 때만 기존 검색 예산(검색 최대2회·문서 읽기 최대2회·60초)으로 품종을 조사한다. 상세 비용과 측정 한계는 `CRITIC_BENCHMARK.md` 참조.
- 검색 당시 와인명·생산자·빈티지를 사용자가 수정하면 점수를 즉시 숨기고 저장하지 않는다. 출처와 짧은 근거를 `critic_scores`에 보관한다. 공개 AI 소믈리에의 출처 없는 expertScore 표시도 제거했다.
- 테이스팅의 수동 푸드 페어링 선택 제거. 검색 추천 기능을 새로 구현한 것은 아니다.
- 레드·화이트·로제·스파클링별 간단 향 목록. 같은 문자열을 전문 모드에서도 선택하므로 모드 전환 시 유지된다. 이미 선택한 다른 유형의 향은 지우지 않고 해제 가능한 항목으로 보인다.
- 간단 입력: 색조/깊이, 향 강도와 대표 향, 단맛·산미·무게감, 레드의 떫은맛, 스파클링 거품, 개인 평점·메모. 음용적기 판단은 제거했다.
- 전문 입력: 더 넓은 향 사전과 외관·향·맛·품질 관찰. 색 깊이3단계, 강도5단계, 단맛6단계, 알코올3단계. 양조/오크 향과 숙성 향 분류 보정. 탁도 자체를 결함으로 취급하지 않는다. 향 숙성 상태와 입안 풍미 메모 안내 추가.
- BLIC는 자체5단계 보조 메모이며 공식 시험 점수로 주장하거나 개인 평점에 자동 합산하지 않는다. WSET 인증/공식 시험 시트라는 표현을 사용하지 않는다.
- 두 언어 전환 시 현재 입력 중인 관찰 항목도 함께 번역한다. 자유 메모는 번역하지 않는다.
- 헤더에 v1.3. package version1.3.0. 다음 작은 수정은1.3.1, 다음 기능 묶음1.4.0, 공개 준비 완료2.0.0. 테스트로 표시 버전/패키지 일치 확인.

## 기준 자료

- WSET의 공식 시음 접근법: https://www.wsetglobal.com/media/11766/wset_l3wines_sat_en_may2022_issue2.pdf
- Vivino 개인 5점 평점 설명: https://www.vivino.com/sv/wine-news/vivino-5-star-rating-system
- 학습·기록을 돕는 도구이며, 사용자의 감각 판단이나 AI 검색 정확도를 보증하는 것은 아니다. 일반적인 유형별 표현은 선택 가이드이며 필수 향/품종 판정 규칙이 아니다.

## 배포 순서

1. `20260919_tasting_v13.sql`: stars를 numeric(2,1)로 변경하고 critic_scores JSONB와 nose_development text 추가. 기존 열·기록/RLS 유지. 0은 과거 미평가 데이터 호환용으로만 허용하며 새 UI는 NULL 저장. 범위 제약은 NOT VALID로 기존 부적합 기록을 일괄 수정하지 않는다.
2. 운영 적용 승인 뒤 위 SQL 실행 → 컬럼 타입/제약 읽기 확인.
3. main 병합 → Vercel Production 준비 완료 확인.
4. 운영 사용자 계정으로 실제 사진 인식·출처 확인과 소수점 저장을 점검. Preview가 운영 Supabase를 사용하면 승인 전 저장 테스트 금지.

## 검증

- 오프라인 단위 테스트: 평점 환산/취향 경계/자료 근거 불일치/평론 점수 범위·빈티지/양 언어 용어 대응.
- PGlite: 전체 스키마와 migration, 소수점4.1 및 출처 JSON 저장·조회, 범위 초과 차단, 기존 RLS/한도.
- 내부 브라우저 로컬 모형 DB: 실제 콘텐츠 너비375px에서 유형4종, 간단→전문, ja→ko 전환, 4.1점 저장 후 셀러 목록/상세 재조회. 운영 고객 데이터 미사용.
- 테스트 50개, lint, TypeScript 검사 포함 운영 빌드 통과. 내부 브라우저에서 향 강도·단맛·떫은맛 연속 드래그 및 5단계 표시, 한국어/일본어 말풍선의 예시 상태를 확인했다.
- 승인된 실제 AI 검색 6회와 운영 DB 변경을 완료했다. 새 소믈리에 한마디의 실제 AI 응답은 아직 별도 실측하지 않았으며 응답 검증/화면은 테스트 데이터로 확인했다.

## 2026-09-19 후속 구현 상세

- **4.0 이상 필터 제거**. 점수를 매긴 모든 기록을 보존·참조한다. 사용자의 가중 평균과 평점 분산으로 상대적 선호 신호를 계산하고, 비슷한 구조의 낮은 평점 기록은 추천 지수를 낮춘다. 고정된4점 기준 없이 까다로운 채점자도 상대적 취향을 비교한다. 비교 가능한 구조2개 이상을 가진3건 이상이 필요하며, 점수 차이가 거의 없거나 비교 근거가 부족하면 지수를 내지 않는다. 소표본은 강한 확신을 줄인다. 확률/검증된 학습모델로 주장하지 않는다.
- 전문가 점수 자동 검색 **사용자 선택으로 OFF**. 실측은 CRITIC_BENCHMARK.md 참조. 기존 출처 보관용 컬럼/검증기는 보존하지만 새 점수 검색은 하지 않는다.
- 입력 슬라이더를 독립 컴포넌트로 유지하여 재렌더 시 입력 DOM이 교체되지 않는다. 간단 모드는5단계 점·번호·라벨과44px 조작 영역. 단맛은 전문6단계 중 간단5개 대표값을 사용하고 전문 입력의 세부값은 덮어쓰지 않는다.
- 酸っぱさ→酸味, 弱い〜強い. 飲み頃 입력과 소믈리에의 음용적기, 셀러의 과거 음용적기 표시를 제거한다. 과거 DB값은 삭제하지 않는다.
- 소믈리에 SVG아이콘·말풍선 추가. 와인 소개는 기존 AI호출에서 출처를 요구해 생성하고, 취향에 맞는지에 관한 문장은 로컬 분석으로 붙인다. 사용자 기록을 새로 외부 AI에 보내지 않는다. 근거 없는 등급·유명세·개인 맞춤 주장은 금지한다. 참고기록 부족 시 취향을 알아가는 표현을 사용한다.
- 사용자 운영 DB 변경/main 병합/배포 승인 수신. `20260919_tasting_v13.sql` 운영 적용 완료, stars numeric 소수점1자리·critic_scores jsonb·nose_development text를 읽기로 재확인했다.
