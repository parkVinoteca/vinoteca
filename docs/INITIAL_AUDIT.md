# Vinoteca 최초 점검 보고서

2026-09-16 / 기준 d164ee0 / 점검 브랜치 codex/initial-audit

## 범위와 한계

실제 GitHub 저장소를 로컬에 복제하여 전체 소스, SQL, lockfile, GitHub 배포 상태를 읽었다. 앱 소스와 SQL, 의존성 버전은 변경하지 않았다. 고객 데이터 조회/생성/삭제, 로그인 제출, 키 입력, 유료 AI 호출, 원격 푸시/배포는 수행하지 않았다.

확인한 운영 브라우저 범위는 비로그인 화면이다. Supabase 운영 RLS/버킷 정책, Vercel 환경변수 분리/방화벽/요금제, Google OAuth 허용 URL, API 계정 예산은 확인하지 못했다. 소스에 존재하는 정책과 실제 운영 정책은 같다고 단정할 수 없다.

## 우선순위별 개선 항목

### P0 — AI 키 보호와 호출 제한

1. `src/components/TastingSheet.tsx:107`에서 Gemini를 브라우저로 직접 호출하며 NEXT_PUBLIC_GEMINI_API_KEY를 사용한다. 해당 변수가 배포 시 설정되면 브라우저 번들로 전달된다. 키의 실제 값이나 운영 노출 여부를 수집하지 않았다. 서버 전용 라벨 API로 옮기고 인증/횟수 제한을 적용하는 것이 최우선이다. 기존 키 교체는 사용자 승인 후 직접 입력 절차로 수행한다.
2. `src/app/api/sommelier/route.ts:5`에는 서버 로그인 검증/사용량 제한이 없다. 이미지 필드가 있으면 외부 호출로 넘어간다. 오프라인 테스트에서도 미인증 요청이 AI mock을 호출하고 200을 반환했다. Vercel 외부 보호 설정은 미확인이다. 성공 후 브라우저에서 ai_usage_logs를 추가하는 방식은 강제 사용량 제한이나 신뢰할 수 있는 과금 기록이 될 수 없다.

### P1 — 보안 업데이트

Next.js 14.2.5가 고정되어 있다. npm audit 결과 취약 패키지 집계는 critical 1(next), high 1(postcss), moderate 1(uuid), 총 3개다. 이는 취약점 개수나 실제 서비스 침해 증거가 아니다. 각 권고의 적용 조건을 확인하고 패치 버전/지원 버전으로 별도 업데이트 검증이 필요하다. 모든 경고가 현재 앱에서 악용된다는 뜻은 아니다.

공식 2025-12-11 공지는 14.x App Router의 서비스 거부 위험을 설명한다. 이 공지만 보고 14.2.35를 현재 최종 안전 버전으로 간주하면 안 된다. 이번 audit에는 더 최근 권고도 포함되어 있다.
https://nextjs.org/blog/security-update-2025-12-11

### P1 — 기록 정확성과 누락

- `src/components/HomeScreen.tsx:22`: 최근 5개만 조회한 결과로 전체 기록 수/평균/자주 마시는 나라를 계산한다. 기록이 6개 이상이어도 홈 기록 수는 최대 5개다.
- `src/components/TastingSheet.tsx:59,172,496`: 입안에서 느낀 메모(palateNotes)를 입력받지만 저장 요청에 포함하지 않는다. 입력이 저장되지 않는 코드 경로가 확인됐다.
- `src/components/BlindMode.tsx:94`: 와인 번호 변경 시 TastingSheet의 key나 초기화 처리가 없어 이전 와인 입력 상태가 이어질 수 있다. 이어서 하기도 완료 기록을 DB에서 복원하지 않고 빈 배열로 시작한다. 로그인 가능한 테스트 환경에서 사용자 흐름 재현이 필요하다.
- DB 삭제/블라인드 완료/여러 목록 조회의 오류를 무시한다. 라벨 업로드 및 Gemini 실패는 콘솔에만 기록되어 사용자가 원인을 알기 어렵다.

### P1 — 취향 점수

`src/lib/tastePofile.ts:28`의 문자열 등급 변환에 오류가 있다. 실제 딕셔너리를 넣은 테스트에서 일본어 6개/한국어 5개 선택값이 잘못 변환됐다. 예: フルボディ는 기대 5인데 3, 중간+는 기대 4인데 3. 언어에 따라 결과가 달라진다.

추가 검토 사항: 구조 평균은 높은 평점 와인만이 아니라 모든 평점 기록으로 계산한다. 현재 식에서는 평균 평점 10, 모든 구조/품종/산지/국가가 일치해도 최대 84점이다. 구조 정보가 누락되어도 기본 구조 점수는 100에서 시작한다. 순수 계산 점수이며 검증된 취향 확률로 표현하면 안 된다. 영문/일문/한글 품종명을 통일하는 코드도 없다.

### P1 — AI 응답 검증과 일본 운영 맥락

- JSON 추출 후 타입/범위 검증이 없다. bodyLevel 999, characteristics 숫자 같은 결과도 200으로 반환하는 것을 mock 테스트로 확인했다. 잘못된 배열 타입은 화면 렌더링 오류로 이어질 수 있다.
- 이미지 크기/형식 검증, 명시적 요청 타임아웃, stop_reason 처리, 검색 실제 실행 확인, 검색 실패 처리, 검증된 출처 URL 구조가 없다. maxDuration은 외부 fetch의 중단 처리가 아니다.
- 한국어 프롬프트는 한국 쇼핑몰/원화를 요청하면서 priceJPY 필드에 넣는다. 일본에서 한국어로 쓰는 사용자의 언어와 가격 시장을 분리해야 한다.
- 공식 Sonnet 5 문서에 따르면 thinking 기본 활성화이며 max_tokens는 추론+답변의 합계 한도다. 현재 1536 제한은 검색 후 JSON이 잘릴 위험이 있으므로 stop_reason/사용량을 측정해야 한다. 실제 호출 없이 위험만 확인했다.
https://platform.claude.com/docs/en/models/sonnet-5/whats-new-sonnet-5

### P1 — DB 재현성과 사진 공개 범위

- `supabase_schema.sql:2`가 아직 만들지 않은 blind_sessions를 참조하므로 빈 DB에서 파일을 위부터 실행하면 실패한다. 운영 DB 상태의 오류라고 단정하지 않는다.
- SQL은 label-images를 공개 버킷으로 정의하고 전체 공개 읽기를 허용한다. 앱은 원본 파일을 압축 전에 업로드한다. 위치 등 사진 메타데이터와 불필요한 배경이 남을 가능성, 저장 용량, 기록 삭제 후 사진 잔존을 검토해야 한다. 실제 사진은 읽지 않았다.
- 로컬 Database 타입은 blind 필드/ai_usage_logs를 모두 포함하지 않고 createClient에 제네릭으로 연결되지 않아 DB 불일치를 타입 검사가 잡지 못한다.
- 운영 정책과 스키마를 먼저 읽기 전용으로 대조한 후 마이그레이션안을 작성해야 한다. 실행에는 명시적 승인이 필요하다.

### P2 — PWA, 언어, 접근성

- manifest는 200이지만 icon-192.png와 icon-512.png는 운영 URL에서도 404다. 테마 색도 화면 팔레트와 다르다. Service Worker/오프라인 구현은 없다. 홈 화면 설치 완료를 검증하지 않았다.
- 일본어/한국어 딕셔너리 키는 일치하지만 로그아웃, 기록 단위 등 하드코딩이 남아 있다. 한국어 선택 후 새로고침 시 일본어로 복귀한다. html lang도 항상 ja다.
- 로그인 이메일/비밀번호 입력칸의 label 연결이 없다(브라우저 DOM에서도 labelCount 0). metadata의 viewport/themeColor 위치에 빌드 경고가 있다. maximum-scale=1 선언, 크롭 모달 키보드 조작/초점 관리도 점검 대상이다.
- 390×844 모바일 viewport를 요청해 확인했고 DOM 보고 너비는 375px, scrollWidth도 375px로 로그인 화면의 가로 넘침은 관찰되지 않았다. 로그인 이후 모바일 화면은 미검증이다.

### P2 — 개발/검증 기반

- 최초 package scripts는 dev/build/start뿐이었다. 테스트, lint, CI, Node 버전 고정이 없다. GitHub Actions 실행 이력은 0개다.
- 새 typecheck/test 명령과 오프라인 회귀 테스트를 추가했다. 앱 변경 금지 범위에 따라 재현한 실패는 그대로 유지했다.
- README 환경변수 설명과 SQL 실행 안내는 보완이 필요하다. `.env`와 `.env.*`가 실수로 추적되지 않도록 ignore를 강화했다. 예외는 `.env.example` 이름뿐이며 비밀값/환경 파일은 만들지 않았다.
- 셀러 목록은 페이지 나누기 없이 전체 조회한다. 성능 변경 전 실제 기록 수와 응답 시간을 측정해야 한다.
